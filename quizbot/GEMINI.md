# QuizBot App Documentation

## Generation Commands

To set up the application and initial data:

```bash
# Install dependencies
pip install -r requirements.txt

# Create the app (if not already present)
python manage.py startapp quizbot

# Apply migrations
python manage.py migrate

# Seed initial data (sample users and topics)
python manage.py setup_quizbot
```

To run tests:

```bash
pytest
```

## Design Choices

### Tech Stack
- **Django**: For the web framework.
- **OpenAI API**: For dynamic question generation using the `gpt-3.5-turbo` model.
- **PostgreSQL**: Primary database.

### Models
- **Topic**: Represents a subject for a quiz. Users can create their own topics.
- **Quiz**: Tracks a user's session for a specific topic, including their current score and completion status.
- **Question**: Stores individual questions generated by the AI, the user's answer, and correctness.

### Difficulty Logic
The quiz asks 5 questions. The difficulty (1-5) increases based on the user's progress. Specifically, the difficulty of the next question is determined by `(number of correct answers so far) + 1`. This ensures that as users get questions right, the quiz becomes more challenging.

### OpenAI Integration
Questions are generated on-the-fly using OpenAI's chat completion with a JSON response format. This ensures that the application always provides fresh content while maintaining a consistent structure for the UI.

### User Experience
- **Login Required**: All quiz features are protected by authentication.
- **Sample Users**: `alice` and `bob` are provided with the password `quizbot123` for easy testing.
- **Immediate Feedback**: Users see their progress (e.g., "Question 2 of 5") and receive a detailed breakdown of their performance at the end.
- **Proficiency Scoring**:
    - 5/5: Expert
    - 3/5 or 4/5: Intermediate
    - < 3/5: Beginner

## Environment & Robustness
- **Environment Variables**: The project uses `python-dotenv` to load configurations from a `.env` file. This is initialized in `project_config/settings.py`.
- **Lazy AI Initialization**: To prevent server crashes when the `OPENAI_API_KEY` is missing, the OpenAI client is initialized lazily in `quizbot/ai.py`. If the key is missing, the app provides a fallback question and logs a warning.
